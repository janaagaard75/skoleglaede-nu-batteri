# Domain docs

This project uses a single context.

## Before exploring

- Read `CONTEXT.md` at the repository root if it exists.
- Read relevant architectural decisions in `docs/adr/` if present.

Proceed silently when these documents are absent. Create domain documentation
when terminology or architectural decisions are resolved, using the
`domain-modeling` skill.

## Vocabulary and decisions

Use the glossary's vocabulary in specs, issues, code and tests. If a concept is
missing, check the existing code's terminology before proposing a glossary entry.
Surface conflicts with existing ADRs before proposing a change.
